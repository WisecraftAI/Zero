# Design Critique Rubric

Use to structure a critique of a screen, flow, or component. Fill as you go; skip sections not applicable.

## 0. Context (filled by designer before critique)

- **What is it?** (screen / flow / component)
- **Who is the user and what are they trying to do?**
- **Constraints** (platform, tech, timeline, brand, legal)
- **What feedback do you want?** (direction, details, alternatives, go/no-go)

## 1. Problem framing

- [ ] Is the user problem clearly stated?
- [ ] Is there evidence this is a real problem (research, data)?
- [ ] Are success criteria named?
- [ ] Are constraints explicit?

**Notes:**

## 2. Information architecture / flow

- [ ] Is the task sequence logical?
- [ ] Are there unnecessary steps?
- [ ] Does navigation match users' mental model?
- [ ] Is backtracking / exit always possible?
- [ ] Are irreversible actions protected?

**Notes:**

## 3. UX heuristics (Nielsen, top applicable)

- [ ] Visibility of system status
- [ ] Match real world
- [ ] User control and freedom
- [ ] Consistency
- [ ] Error prevention
- [ ] Recognition over recall
- [ ] Flexibility / efficiency
- [ ] Minimalist
- [ ] Error messages (plain, specific, fixable)
- [ ] Help / documentation in context

**Notes:**

## 4. Visual hierarchy

- [ ] Squint test: primary action obvious?
- [ ] Single primary CTA per screen?
- [ ] Size, weight, color, position aligned with importance?
- [ ] Whitespace used to group and emphasize?

**Notes:**

## 5. Typography

- [ ] Body size >= 16px (or 14px justified)?
- [ ] Line length 45-75 characters?
- [ ] Leading 1.4-1.6 for body?
- [ ] No more than 2 typefaces?
- [ ] Numerals tabular where appropriate?

**Notes:**

## 6. Color

- [ ] Contrast: body 4.5:1, large/UI 3:1?
- [ ] Semantic colors used for state (not decoration)?
- [ ] Not relying on color alone for meaning?
- [ ] Brand vs hierarchy vs state distinct?
- [ ] Dark mode considered?

**Notes:**

## 7. Layout and spacing

- [ ] Alignment: every element aligns to something?
- [ ] Spacing on the scale (4/8pt)?
- [ ] Grid used consistently?
- [ ] Responsive behavior designed (not just desktop)?

**Notes:**

## 8. Components and states

- [ ] Uses design system components where they exist?
- [ ] All states drawn (default, hover, focus, active, disabled, loading, error, empty, success)?
- [ ] Empty state teaches next action?
- [ ] Error states recover, not just report?

**Notes:**

## 9. Accessibility

- [ ] Contrast passes WCAG AA?
- [ ] Touch targets 44pt / 48dp?
- [ ] Keyboard navigable, focus visible?
- [ ] Color-independent cues for state?
- [ ] Alt text / labels / semantics implied?
- [ ] Motion respects `prefers-reduced-motion`?

**Notes:**

## 10. Copy and content

- [ ] Language is the user's, not the company's?
- [ ] Short, specific, actionable?
- [ ] Error messages constructive?
- [ ] Jargon flagged and replaced?
- [ ] Tone consistent with brand voice?
- [ ] Inclusive language?

**Notes:**

## 11. Edge cases

- [ ] Long names / text overflow
- [ ] Zero / one / many
- [ ] Slow network
- [ ] Offline
- [ ] Non-English content
- [ ] RTL if applicable
- [ ] Large text (accessibility sizing)
- [ ] Permission denied / auth expired
- [ ] Empty / error / partial data

**Notes:**

## 12. System impact

- [ ] New components introduced (justified)?
- [ ] Uses existing tokens and patterns?
- [ ] Changes that affect other product areas?
- [ ] Documentation updates needed?

**Notes:**

## 13. Business and technical

- [ ] Aligned with product strategy?
- [ ] Technically feasible in timeline?
- [ ] Measurable? What metric moves?
- [ ] Dependencies / blockers?

**Notes:**
