ZER0 Web

LLD for @zero/web (web/) — the React 18 + Vite SPA. Presentation and form validation only. No Playwright, no Postgres, no cloud SDKs. Talks to @zero/api over same-origin /api/*.

Package @zero/web
Folder web/src/
Build → dist/web/
Dev :5173 → proxy :3000

Purpose

What the SPA is for — and what it deliberately is not.

The Web UI is the human front door to the QA orchestration pipeline. Operators create runs against an OTT/target URL, watch stage progress, inspect artifacts (requirements, TCs, scripts, reports), manage LLM provider keys / agent prompts, and feed locator intelligence.

Owns

Presentation

Views, forms, validation, pipeline visualization, download links, theme.

Owns

Client orchestration

View switching, run list refresh, 1.5s poll while a run is active, FormData assembly.

Never

Business logic

No stage DAG, no Playwright, no secret decryption, no artifact byte proxying, no pg/cloud SDKs.

How it communicates

Transport, proxy, and the API contract the SPA actually uses today.

Transport model

Browser

fetch() + FormData + window.open

Relative URLs (/api/…). No axios, no react-query, no EventSource yet.

Dev proxy

Vite server.proxy

/api, /artifacts, /health → http://localhost:3000. Same-origin in production when API serves dist/web/.

API

@zero/api · services/api/

Only HTTP peer. Orchestrator / executor are invisible to the SPA — progress arrives as run JSON.

Out of band

State maintenance

Where truth lives — client memory vs server vs browser storage.

Ownership model

Derived UI (no separate store)

  • PipelineFlow — reads run.stages[*].status; optional stages appear only when present.
  • RunDetail tabs — getVisibleTabs(run) filters optional tabs from artifacts / stages.
  • Dashboard stats — computed from runs[] (counts, avg pass rate).
No global store. There is no Redux / Zustand / Context for runs. Props drill from App → shell → views. Scaling concern for V3 src/data/ hooks (one hook per endpoint).

Patterns in play

Structural

Container / Presentational

App.jsx owns data & side effects. Views mostly render props + local form state. Shell is layout-only.

Structural

Shell layout

AppShell = Sidebar + Topbar + outlet. Topbar props derived from current view + active run.

Behavioral

View switch (manual SPA router)

String view + switch — no react-router. Navigation is navigate(to, runId?).

Behavioral

Polling observer

Interval subscription while run is live; tears down on terminal status or id change.

Creational

FormData builder

NewRunView validates, then constructs multipart payload (files, mode, recording ids) before handing to App.

UI

Wizard / multi-step form

NewRun steps: Input → Assets → Creds → Options → Recording. Step index is local state.

UI

Colocated styles

Each view/component imports its own .css. Global tokens in index.css / App.css.

Boundary

BFF-via-same-origin

SPA never addresses orchestrator/executor. API is the single façade (Backend-for-Frontend shape without a separate BFF process).

Constraints (honour these)

  • Edit web/src/** only for UI behavior; rebuild with npm run build → dist/web/.
  • Do not import playwright, pg, AWS/GCP SDKs, or @zero/cloud.
  • Prefer EventSource on /api/runs/:id/stream when replacing the poller — do not add more polling endpoints.
  • Passwords: never localStorage, never console logs.

Guardrails while doing this

  • No new polling endpoints — SSE first, poll only as fallback.
  • Keep the client free of playwright, pg, cloud SDKs, @zero/cloud.
  • Rebuild with npm run build; never hand-edit dist/web/.
  • Passwords stay runtime-only — never localStorage, never logs.
Definition of done. A run started from the UI streams stage ticks over SSE, uploads via presigned PUT, survives reload via a deep link, and all network access flows through src/data/ hooks.
