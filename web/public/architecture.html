Architecture Docs

ZER0

Runtime today, the production blueprint, the ship checklist, and the V3 repo + Docker shape — one page, five tabs. Grounded in services/api, @zero/orchestrator, @zero/executor, and packages/*, aimed at the multi-cloud target in public/architectureV2.html.

What ZER0 is for

One tool that compresses the QA architect + BA + manual + automation workflow behind a single URL.

Give ZER0 an OTT URL and any of a test-case file, Figma link, or plain notes. It produces consolidated requirements, an app-specific manual test-case list, Playwright + Java/Selenium scripts, a Playwright execution report with screenshots, and Manager / Delivery reports as PDF or JSON.

The point is not "another test recorder." It's a single run that turns a link into a full QA artifact set — usable by a solo QA on day one and portable into your real Java/Maven suite when you want production coverage.

Who it's for

Built for teams doing OTT / streaming / e-commerce QA under time pressure.

QA architects & leads

Need consistent BRD → TC → script → report traceability across many channels. Get it in one run.

Solo QA on a new product

No test suite yet. Feed the site URL, pick a profile, get a manual list and a Java suite you can adapt.

Delivery managers

Need a stakeholder-ready Manager / Delivery report per run without chasing four people for pieces.

Automation engineers

Use the generated Playwright spec and Java/Selenium class as scaffolding; own execution in your own CI.

How it works under the hood

HTTP intake in @zero/api; the DAG worker in @zero/orchestrator; Chromium only in @zero/executor.

  1. Intake: UI POSTs to /runs. services/api/server.js creates the run (in-memory Map + artifacts/<runId>/run.json, and Postgres when configured), then publishes runs.requested.
  2. Stages: @zero/orchestrator processRun walks stageKeys from @zero/domain. Agents use templates by default; LLM when a decrypted provider key exists.
  3. Locators: @zero/locators merges channel-profile selectors + this-run learned selectors + (when DB is on) Postgres locators per host.
  4. Execution: orchestrator publishes execution.requested; @zero/executor launches Chromium; screenshots land under artifacts/<runId>/.
  5. Reports: pdfkit renders the Manager PDF; Delivery emits JSON. The UI uses GET /runs/:id or SSE /stream until completed.
  6. Reuse: the Java/Selenium class is generated by @zero/builders (javaSeleniumBuilder) from the same locator merge.

Recording bookmarklet + /record page lets you capture real DOM element logs from any site; those feed the locator registry too.

How to run

From the repository root.

npm install
npx playwright install chromium

# builds the React SPA (web/) into public/
npm run build

# API only (services/api/server.js · default PORT=3001)
npm start

# local all-in-one: API + orchestrator + executor
npm run start:all

Paste-safe: run each line separately. zsh has INTERACTIVE_COMMENTS off by default, so inline # comments get forwarded to vite build and the build fails with Could not resolve entry module "#/index.html". Enable once with setopt interactive_comments.

  • Input: OTT URL required, plus at least one of Figma / TC file / BA notes (or Web Analyzer fills gaps).
  • Default execution: minimal — load URL + screenshot so the pipeline completes.
  • Full mode: EXECUTION_MODE=full for keyword/selector navigation (brittle).

Postgres is optional: when DATABASE_URL or PGHOST is set, @zero/db activates (qa_runs / qa_assets + locator tables). Otherwise runs persist to artifacts/<id>/run.json + in-memory Maps.

Why the shape has to change

Today's runtime hits five walls before it can go multi-tenant on any cloud.

Serverless ≠ Playwright

Vercel functions can't host long-running Chromium. Execution must move to a durable worker host.

State in Maps

runs, runSecrets, recordingSessions, selectorMemory — all in-process. Zero horizontal scale.

Local disk artifacts

artifacts/ is a filesystem path. Serverless has no persistent disk; workers can't share it.

API does the work

processRun runs stages inside the request. Retries, back-pressure, and fan-out are impossible.

Postgres optional

Once orchestrators scale out, memory can't hold state. DB + Redis become required, not optional.

Vendor-shaped code

To move between AWS / GCP / Azure the domain code must stop knowing which SDK it's talking to.

Three tiers with one contract

Split ZER0 into stateless intake, orchestration workers, and ephemeral execution — everything else hides behind adapters.

  Tier              Runtime                       Owns

Rollout milestones

Order matters — each milestone unblocks the next.

M1

Durable store

Restore databaseConfigured(), wire Postgres for qa_runs, qa_assets, element_locators. Kill in-memory Maps.

M2

Object store + signed URLs

Move artifacts/ off local disk. Browser uploads via presigned PUT. API never streams big bodies.

M3

Queue + orchestrator

Extract processRun into a worker consuming runs.requested. API returns immediately.

M4

Execution farm

Playwright runs in container jobs behind execution.requested. Fan-out per TC batch; retries via queue.

M5

Auth + ACL

Real OIDC, per-tenant scoping on runs and artifacts, presigned reads only.

M6

LLM wiring

Provider keys UI actually calls BA/Manager. Add rate-limit, cost caps, prompt versioning.

M7

Multi-cloud adapters

packages/cloud (@zero/cloud) implementations for AWS + GCP (and local). IaC modules per provider. Smoke tests in CI.

P0 · blockers before any external use

These are correctness or safety issues, not polish.

P1 Postgres still optional locally

When unset, memory + artifacts/ remain the fallback. Multi-instance and locator reuse need DATABASE_URL / PGHOST and Redis for shared state.

P1 Auth must be on in every deploy

Verified API key / JWT scopes runs by tenant. X-User-Email is not identity. Keep ZERO_AUTH=on (forced in production) and a real KEY_ENC_SECRET.

P1 Artifact + recording CORS discipline

/artifacts is not statically served; use signed downloads. Recording CORS must stay an explicit origin allowlist — never * in production.

P1 Local stack must co-locate workers

npm start is API-only. Chromium lives in @zero/executor — use npm run start:all or Compose, and respect ZERO_EXEC_CONCURRENCY.

P0 Minimal execution ≠ E2E proof

Default checks pass on URL load. Manager "Go" must not be treated as release proof without full mode or external runners.

P1 · gaps before scale

These bite the moment there's more than one instance or user.

P1 Memory-bound state

Runs, recordings, secrets, selector memory are Maps — broken across instances and restarts (except run.json).

P1 Wrong host for Playwright

Vercel /tmp + serverless timeouts vs long Chromium work; need a durable worker host.

P1 Default encryption secret

KEY_ENC_SECRET falls back to a fixed dev string — refuse to start in production without it.

P1 Ops / config

No tests despite Jest; CSP allows unsafe-eval; CORS wildcards for Railway/Vercel; example env embeds a live hostname.

P2 · later

Real improvements, but not blockers.

P2 LLM still template-first

BA/Manual/Automation/Manager call Claude/OpenAI/Gemini only when a decrypted key exists; otherwise templates.

P2 IDE vision unfinished

No /projects; stored scripts / recordings tables are not the live run path.

P2 Middleware / SPA catch-all

Routes live under services/api/src/routes/; keep error handlers ordered ahead of the SPA fallback.

Recommended sequence

One right order to attack the list without wasted work.

  1. Run with durable store — set DATABASE_URL / PGHOST so @zero/db persists runs and locators.
  2. Auth + artifact ACL — verified API key / JWT; keep artifacts off the public static path.
  3. Queued Playwright workers — already split to @zero/executor; run via start:all or Compose.
  4. Honest Go / No-Go semantics — minimal execution stops implying release proof.
  5. Wire or defer LLM — either connect the key UI, or hide it until it works.
  6. CI smoke + container image — one repeatable image, one green test path.

Chromium stays in executor

Shared code is packages

Former lib/* modules are @zero/* packages. Workers import by package name, not relative repo paths.

Object store + local artifacts

ZERO_CLOUD=local stores blobs under artifacts/cloud-store with signed URLs; filesystem artifacts/<runId>/ remains for run JSON / screenshots.

V3 is a packaging change, not a redesign. The tiers, primitives, and @zero/cloud (packages/cloud) contracts stay exactly as drawn in architectureV2.html. V3 decides which files live where and which image runs them.

Migration order

Restructuring is worthless if it stalls halfway. This order keeps the app runnable after every step, and lines up with the M1–M7 milestones in agent-workflow/.

S0

Containerize what exists · done

One Dockerfile + docker-compose.yml for today's monolith, plus Postgres/Redis/MinIO. No code moves. This alone gives a reproducible environment and unblocks M1.

S1

Add a smoke test · done

Jest boots the app, starts a run, and (when Postgres is up) asserts a qa_runs row. Without that, splitting the former monolith is unverifiable.

S2

Turn on workspaces · done

Root is workspaces-only. Former lib/* is packages/* (@zero/*); former client/ is web/. Imports use package names.

S3

Split routes from stages · done

HTTP routes live in services/api/src/routes/*; DAG walk in @zero/orchestrator (processRun.js). API no longer embeds the pipeline.

S4

Extract the executor

Move Chromium behind execution.requested. Now playwright can leave the API image. Delivers M4, the acceptance floor.

S5

Extract the orchestrator

Its own image consuming runs.requested. API returns 202 immediately and relays status over SSE from Redis pub/sub. Delivers M3.

S6

Swap local adapters for cloud

ZERO_CLOUD=aws and friends under packages/cloud, with infra/ Terraform per provider. Delivers M7.

Current position: S0 + S1 + M1–M7 are done. ZERO_CLOUD=aws|gcp adapters and IaC ship; default runtime is still local.

Adapter template · AWS queue

Same shape as packages/cloud/local/queue.js. Domain code sees identical publish / subscribe.

// packages/cloud/aws/queue.js
'use strict';
const { SQSClient, SendMessageCommand, ReceiveMessageCommand,
        DeleteMessageCommand } = require('@aws-sdk/client-sqs');

const region = process.env.AWS_REGION || 'us-east-1';
const client = new SQSClient({ region });                 // IRSA / task role
const topicToUrl = {
  'runs.requested':      process.env.SQS_URL_RUNS,
  'execution.requested': process.env.SQS_URL_EXEC,
  'execution.completed': process.env.SQS_URL_EXEC_DONE,
};

async function publish(topic, msg, opts = {}) {
  const QueueUrl = topicToUrl[topic];
  if (!QueueUrl) throw new Error(`Unknown topic: ${topic}`);
  await client.send(new SendMessageCommand({
    QueueUrl,
    MessageBody: JSON.stringify(msg),
    MessageDeduplicationId: opts.dedupId,      // FIFO queues only
    MessageGroupId:         opts.groupId,      // FIFO queues only
  }));
}

function subscribe(topic, handler) {
  const QueueUrl = topicToUrl[topic];
  let stopped = false;
  (async function loop() {
    while (!stopped) {
      const { Messages = [] } = await client.send(new ReceiveMessageCommand({
        QueueUrl, MaxNumberOfMessages: 10, WaitTimeSeconds: 20,
        VisibilityTimeout: 300,                // longer than the slowest handler
      }));
      for (const m of Messages) {
        try {
          await handler(JSON.parse(m.Body));
          await client.send(new DeleteMessageCommand({
            QueueUrl, ReceiptHandle: m.ReceiptHandle,
          }));
        } catch (err) {
          // leave on queue → SQS redrives to DLQ after maxReceiveCount
          console.error('[aws.queue] handler error:', err);
        }
      }
    }
  })();
  return () => { stopped = true; };
}

module.exports = { publish, subscribe };

// packages/cloud/gcp/storage.js
'use strict';
const { Storage } = require('@google-cloud/storage');

const bucket = new Storage().bucket(process.env.GCS_BUCKET);

module.exports = {
  async presignPut(key, ttlSec = 900) {
    const [url] = await bucket.file(key).getSignedUrl({
      version: 'v4', action: 'write',
      expires: Date.now() + ttlSec * 1000,
      contentType: 'application/octet-stream',
    });
    return url;
  },
  async presignGet(key, ttlSec = 900) {
    const [url] = await bucket.file(key).getSignedUrl({
      version: 'v4', action: 'read',
      expires: Date.now() + ttlSec * 1000,
    });
    return url;
  },
  put:    (key, body, meta) => bucket.file(key).save(body, { metadata: meta }),
  get:    (key)              => bucket.file(key).createReadStream(),
  remove: (key)              => bucket.file(key).delete().catch(() => {}),
};

How do you know it doesn't smell?

Ten enforceable gates. Each is a command that returns non-zero on regression. If they're not in CI, the split rots inside a month.

GATE-1 API image contains no browser

docker run --rm zero-api ls -R node_modules | grep -E 'playwright|chromium' && exit 1 || true. Prevents Chromium from silently re-entering the stateless tier.

GATE-2 No cross-app imports

npx depcruise services/api --config .dependency-cruiser.js with a rule that forbids services/* importing anything under a sibling services/*. Apps talk via queue only.

GATE-3 Domain code doesn't know AWS/GCP/Azure exist

rg "from '@aws-sdk|@google-cloud|@azure/" services packages -g '!packages/cloud/**' && exit 1. Only packages/cloud/{aws,gcp,azure} may import vendor SDKs.

GATE-4 No circular deps

npx madge --circular packages services. First circular import is where the split starts leaking.

GATE-5 API package size budget

docker image inspect zero-api --format '{{.Size}}' stays under 250 MB. Regressions usually mean a stray transitive dep dragged Playwright or Puppeteer back in.

GATE-6 No process.env outside config.js

rg "process\\.env\\." services -g '!**/config.js' -g '!**/*.test.js'. Every service reads env exactly once at boot; the rest of the code takes a validated config object.

GATE-7 No console.log in shipped code

rg "console\\.(log|error|warn)" services packages -g '!**/*.test.js'. Use the structured logger from @zero/observability.

GATE-8 No secrets in artifacts

Test that greps run artifacts for known secret shapes (JWT, AWS key, bearer) and fails the build. services/api/apiKeyManager exists; enforce it.

GATE-9 Contract tests on adapters

Every provider under packages/cloud/* passes the same conformance suite: presignPut · presignGet · put · get · remove · publish · subscribe · get · set · publish · subscribe. Same test file, four provider fixtures.

GATE-10 Migrations are forward-only + reversible

packages/db/migrate.js up && migrate.js down && migrate.js up succeeds in CI. No hand-edited SQL after merge.

Wire order: gates 1–5 in a required pre-merge job (block merge); gates 6–8 in a nightly job that files issues; gates 9–10 in the release job.

Per-workspace conventions

Non-negotiable rules that keep the split healthy. Enforced by the gates above.

Every workspace

type: "module", Node 20 LTS · one src/ tree · one test/ tree · src/config.js is the only reader of process.env and exports a frozen, zod-validated object · src/logger.js re-exports pino/winston from @zero/observability with a bound service name · exports declared in package.json#exports, no deep imports.

services/api

Route files return a router only; no side effects at import · zod schemas at the boundary, typed handlers · every route returns within 250 ms budget or streams · SSE handlers use cache.subscribe, never poll DB · errors funnel through one errorHandler middleware that maps to { code, message, requestId }.

services/orchestrator

One agent = one file, one exported run(runId, ctx) · agents receive a ctx with db · objectStore · secrets · llm · logger — never call adapters directly · every write is idempotent on (runId, stage) · retries are the queue's job, not the agent's · no setTimeout-based waits.

services/executor

One job = one browser context, always closed in finally · per-step timeout via page.setDefaultTimeout · screenshots and traces uploaded through objectStore, never written next to the process · learned selectors upserted in a single batched statement · no HTTP server, only queue subscription.

packages/cloud

Each provider exports the exact same surface as index.d.ts — the conformance suite (GATE-9) is the source of truth · no cross-provider imports · adapters throw typed errors (NotFound · Conflict · Throttled) that the domain code can switch on without knowing the vendor.

packages/domain, locators, builders, analyzer, db

Pure functions where possible, no I/O at import · zero dependencies on express, playwright, or cloud SDKs · snapshot tests for anything that emits code (Playwright spec, Java class) · db package owns migrations and a thin pg pool factory only.

web

One view = one folder, colocated .css · data-fetching hooks live under src/data/, never inside components · no useEffect for server state — use a query hook · SSE via a single provider that debounces state updates · axe smoke test per view.

Cross-cutting concerns

Concerns that touch every service. Standardize once, or every app reinvents them badly.

Observability

OpenTelemetry SDK auto-instruments express/pg/aws-sdk. One traceparent follows a run across api → queue → orchestrator → executor. Logs are JSON via pino, always include runId, service, traceId. Metrics: runs_started, runs_completed, stage_duration_ms, queue_lag, executor_slots_used.

Config

src/config.js = zod.parse(process.env). Boot fails fast on missing/invalid config. Never read env below this file.

Secrets

Only secrets.get(). Prod refuses to boot if KEY_ENC_SECRET falls back to the dev default. Login passwords for a run never enter Postgres or artifacts.

Health & readiness

/health liveness (200 if event loop alive). /ready checks DB, queue, object store round-trip. K8s probes: liveness=/health, readiness=/ready.

Error taxonomy

Four base classes in @zero/domain/errors: ValidationError → 400, NotFound → 404, Conflict → 409, InternalError → 500. Handlers throw; middleware maps.

Auth & multi-tenant

OIDC verifier on api; every DB write scoped by tenant_id; presigned reads only. Adapter surface has no tenant knowledge — namespacing happens in @zero/domain.

Risks & tradeoffs

Where V3 is fragile, and what to do about it.

R1 Adapter drift

Provider adapters silently diverge in edge behavior (retry semantics, error shapes, event ordering). Mitigation: the shared conformance suite (GATE-9) runs against every provider in CI; providers without green cannot ship.

R2 Executor cold start

Chromium image is ~1.6 GB and slow to schedule. First job of the day can wait 30–60 s. Mitigation: keep min_replicas=1 for the executor deployment; autoscale up on queue depth, not on CPU.

R3 Queue exactly-once fantasy

SQS/PubSub/Service Bus all deliver at-least-once. Idempotency must live in the handler, not the queue. Mitigation: every write keyed by (runId, stage); DB uniqueness catches replays.

R4 Monorepo build times

Naive builds rebuild everything on any change. Mitigation: turborepo or nx with per-workspace caches, or lockfile-only copy in Dockerfiles (already shown) so npm ci caches across commits.

R5 SSE behind load balancers

Sticky sessions or cache-fanout matter. If the API is behind an LB without sticky, one replica publishes state and another holds the connection. Mitigation: every replica subscribes to Redis pub/sub for state.<runId>; no stickiness required.

R6 Local ≠ prod for signed URLs

packages/cloud/local uses HMAC tokens served by the API; real S3/GCS use SigV4/V4. Auth failures only surface in staging. Mitigation: at least one nightly job that exercises the AWS adapter against LocalStack.

R7 LLM provider outages

BA/Manager stages fail if OpenAI/Anthropic/Vertex hiccup. Mitigation: agents accept a llm facade with per-provider fallback and a deterministic template mode (today's runtime), so a run can still complete with degraded reports.

Definition of done for V3: gates 1–5 green in required CI · smoke e2e green on docker compose up · one non-local provider (AWS or GCP) passes the conformance suite · agent-workflow/progress.json shows M4 complete (acceptance floor).

Timeouts, retries, isolation

  • Per-step timeout: page.setDefaultTimeout(30000).
  • Per-job budget: 5 min. Exceeded → screenshot, mark failed, close context.
  • Queue visibility: 6 min (job budget + slack). Prevents redelivery mid-run.
  • Retry: queue redrives once on crash; DLQ on second failure.
  • Isolation: new browserContext per job — no cookies/storage leak across tenants.
  • Node sizing: 1 vCPU + 2 GB RAM + 1 GB /dev/shm per concurrent job.

Config & failure

  • Config: MAX_CONCURRENT_JOBS, EXECUTION_MODE, PLAYWRIGHT_TIMEOUT_MS, JOB_TIMEOUT_MS.
  • OOM: job killed by cgroup → queue redrives once → DLQ; run marked partial.
  • Selector miss: record miss, try next candidate from merge order, fail TC only after exhausting.
  • Long tail: executor autoscales on queue_depth, not CPU (Chromium is CPU-idle while waiting).

Cross-package rules

  • No app imports: a package must not import from services/* — enforced by GATE-2.
  • No vendor SDK imports: only packages/cloud/{aws,gcp,azure} may import @aws-sdk/* etc — enforced by GATE-3.
  • Zero I/O at import time: importing a package must not open connections, spawn processes, or read env — config.js is only inside services.
  • Semver: internal packages pinned by workspace protocol (workspace:*); breaking changes bump the major before merge.
