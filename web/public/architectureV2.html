Architecture Docs

ZER0

Runtime today, the production blueprint, the agent prompt to build it, and the ship checklist — one page, five tabs. Grounded in services/* + packages/* (@zero/*), aimed at the multi-cloud target in support/zero-docs/docs/v2/ARCHITECTURE.md. Packaging S0–S6 and capability M1–M7 are shipped.

What ZER0 is for

One tool that compresses the QA architect + BA + manual + automation workflow behind a single URL.

Give ZER0 an OTT URL and any of a test-case file, Figma link, or plain notes. It produces consolidated requirements, an app-specific manual test-case list, Playwright + Java/Selenium scripts, a Playwright execution report with screenshots, and Manager / Delivery reports as PDF or JSON.

The point is not "another test recorder." It's a single run that turns a link into a full QA artifact set — usable by a solo QA on day one and portable into your real Java/Maven suite when you want production coverage.

Who it's for

Built for teams doing OTT / streaming / e-commerce QA under time pressure.

QA architects & leads

Need consistent BRD → TC → script → report traceability across many channels. Get it in one run.

Solo QA on a new product

No test suite yet. Feed the site URL, pick a profile, get a manual list and a Java suite you can adapt.

Delivery managers

Need a stakeholder-ready Manager / Delivery report per run without chasing four people for pieces.

Automation engineers

Use the generated Playwright spec and Java/Selenium class as scaffolding; own execution in your own CI.

How people use it

Six steps, from browser open to shippable report.

02

Create a new run

Enter the OTT URL, pick a channel profile, and provide any of: TC file (.csv, .xlsx, .txt, .md, .json), a Figma link, or BA notes.

03

Choose options

Enable accessibility, performance, or security passes. Add login credentials (runtime-only). Toggle "show browser" for a headed Chromium.

Watch the pipeline

Stages tick through in the detail view — BA → Manual → Automation → Execution → optional passes → Manager → Delivery.

05

Download requirements, manual TC list, Playwright spec, Java/Selenium class, PDF or JSON reports.

06

Take Java to prod

Drop the generated Java class into your Maven/Gradle project, tune the locators for your app, run in your CI.

How it works under the hood

Three tiers: HTTP API intake, orchestrator DAG worker, Playwright executor — Chromium only in the executor.

  1. Intake: UI POSTs to /api/runs (multipart or JSON + presigned uploads). services/api creates the run, persists to artifacts/<runId>/run.json (+ Postgres when configured), and publishes runs.requested.
  2. Stages: @zero/orchestrator processRun walks stageKeys from @zero/domain. BA / Manual / Automation / Manager use templates, and call Claude / OpenAI / Gemini when a decrypted provider key exists (ZERO_LLM=off forces templates).
  3. Locators: @zero/locators merges channel-profile selectors + this-run learned selectors + (when enabled) Postgres locators per host.
  4. Execution: orchestrator publishes execution.requested; @zero/executor launches Chromium; screenshots and traces land under artifacts/<runId>/ (or object store).
  5. Reports: Manager PDF + Delivery JSON; UI uses GET /api/runs/:id and SSE /api/runs/:id/stream until status is completed.
  6. Reuse: the Java/Selenium class is generated by @zero/builders (javaSeleniumBuilder) from the same locator merge, so you can lift it into any Java project.

Recording bookmarklet + /record page lets you capture real DOM element logs from any site; those feed the locator registry too.

How to run

From the repository root.

npm install
npx playwright install chromium

# builds the React SPA (web/) into public/
npm run build

# API only (default PORT=3000) — services/api/server.js
npm start

# local all-in-one: API + orchestrator + executor
npm run start:all

Paste-safe: run each line separately. zsh has INTERACTIVE_COMMENTS off by default, so inline # comments get forwarded to vite build and the build fails with Could not resolve entry module "#/index.html". Enable once with setopt interactive_comments.

  • Input: OTT URL required, plus at least one of Figma / TC file / BA notes (or Web Analyzer fills gaps).
  • Default execution: minimal — load URL + screenshot so the pipeline completes.
  • Full mode: EXECUTION_MODE=full for keyword/selector navigation (brittle).
  • Compose: docker compose up --build runs split API / orchestrator / executor images.

Postgres: when DATABASE_URL or PGHOST is set, runs upsert to Postgres via @zero/db. If unset or unreachable, the process falls back to memory + artifacts/<id>/run.json.

Why the shape had to change

The pre-split monolith hit five walls before multi-tenant multi-cloud was possible. Capability M1–M7 and packaging S0–S6 addressed them; the blueprint below is the shape that shipped.

Serverless ≠ Playwright

Vercel functions can't host long-running Chromium. Execution must live in a durable worker host (services/executor).

State in Maps

runs, runSecrets, recordingSessions, selectorMemory — in-process alone blocks horizontal scale. Postgres + Redis/object store are the durable path.

Local disk artifacts

artifacts/ alone is not enough for serverless or shared workers — object store + signed URLs.

API does the work

processRun must not run stages inside the request. Orchestrator workers + queues enable retries and fan-out.

Postgres optional → required at scale

Once orchestrators scale out, memory can't hold state. DB + cache become required for multi-instance.

Vendor-shaped code

To move between AWS / GCP / Azure / Vercel the domain code must stop knowing which SDK it's talking to — @zero/cloud.

Three tiers with one contract

Split ZER0 into stateless intake, orchestration workers, and ephemeral execution — everything else hides behind adapters.

  Tier              Runtime                       Owns
  ────────────────────────────────────────────────────────────────
  edge + api        stateless containers /         auth, run intake,
                    serverless functions           status stream, signed URLs

  orchestration     long-lived workers             BA · Manual · Automation ·
                                                   Manager · Delivery agents,
                                                   LLM calls, DAG state

  execution         ephemeral job containers       Playwright chromium runs,
                                                   screenshots, element logs

Contract: every tier only talks to four provider-agnostic primitives — queue, object store, relational DB, and KV / secrets. Cloud SDKs live in packages/cloud (@zero/cloud) adapters, never in agents.

Sequence · start-to-report

One run, 36 numbered hops, four phases. The rule: no two services hand work to each other in memory — every hop crosses Postgres, the object store, the event bus, Redis, or the secrets manager, so any service can restart or scale out without losing the run.

Read it as four questions. Who accepted the work and made it durable (A) · who decided what to test (B) · who actually drove a browser (C) · who assembled the answer and handed it back (D). Restart any single service mid-run and the next phase can still rebuild its context from Postgres and the object store.

Today: under the default ZERO_CLOUD=local, steps 1–6, 8 and 19–27 execute inside one process — the boundaries are function calls through @zero/cloud, not network hops. Compose already runs API, orchestrator, and executor as three images; switching ZERO_CLOUD to aws, gcp, azure, or vercel makes every hop real without touching agent code.

Cloud adapter contracts

Tight interfaces so the domain code never imports a vendor SDK.

// packages/cloud/index.d.ts

export interface ObjectStore {
  presignPut(key: string, ttlSec?: number): Promise<string>;
  presignGet(key: string, ttlSec?: number): Promise<string>;
  put(key: string, body: Buffer | Readable, meta?: object): Promise<void>;
  get(key: string): Promise<Readable>;
  remove(key: string): Promise<void>;
}

export interface Queue<T> {
  publish(topic: string, msg: T, opts?: { dedupId?: string }): Promise<void>;
  subscribe(topic: string, handler: (msg: T) => Promise<void>): Unsubscribe;
}

export interface Secrets {
  get(name: string): Promise<string>;
  put(name: string, value: string): Promise<void>;
}

export interface Cache {
  get<T>(key: string): Promise<T | null>;
  set<T>(key: string, val: T, ttlSec?: number): Promise<void>;
  publish(channel: string, msg: unknown): Promise<void>;
  subscribe(channel: string, cb: (msg: unknown) => void): Unsubscribe;
}

// wired once at boot from process.env.ZERO_CLOUD = "local" | "aws" | "gcp" | "azure" | "vercel"

Rollout milestones

Order mattered — each milestone unblocked the next. Capability track M1–M7 is done; packaging S0–S6 is done.

M1

Durable store

Restore databaseConfigured(), wire Postgres for qa_runs, qa_assets, element_locators via @zero/db. Kill sole reliance on in-memory Maps.

M2

Object store + signed URLs

Move artifacts/ off local disk. Browser uploads via presigned PUT. API never streams big bodies.

M3

Queue + orchestrator

Extract processRun into a worker consuming runs.requested. API returns immediately.

M4

Execution farm

Playwright runs in container jobs behind execution.requested. Fan-out per TC batch; retries via queue.

M5

Auth + ACL

Real OIDC / verified API keys, per-tenant scoping on runs and artifacts, presigned reads only.

M6

LLM wiring

Provider keys UI actually calls BA/Manager (and Manual/Automation). Rate-limit, cost caps, prompt versioning.

M7

Multi-cloud adapters

packages/cloud (@zero/cloud) for local · aws · gcp · azure · vercel (GATE-9 conformance). IaC modules per provider. Smoke tests in CI.

## North-star shape (do not redesign)
Three tiers, one contract:
- **API** — auth, run intake, status/SSE, signed URLs. Never runs Chromium. Folder `services/api/`, npm `@zero/api`.
- **Orchestrator** — BA · Manual · Automation · Manager · Delivery, LLM calls, DAG state. Consumes `runs.requested`. Folder `services/orchestrator/`, npm `@zero/orchestrator`.
- **Execution farm** — ephemeral Playwright jobs on `execution.requested`; screenshots/traces to object store. Folder `services/executor/`, npm `@zero/executor`.

Every tier talks only through provider-agnostic primitives in `packages/cloud` (`@zero/cloud`):
`queue` · `object store` · `relational DB` · `KV/cache` · `secrets`.
Wire once from `process.env.ZERO_CLOUD` = `local` | `aws` | `gcp` | `azure` | `vercel`. Domain/agent code must not import vendor SDKs.

Honor the numbered start-to-report sequence on the blueprint page (presigned uploads → Postgres `qa_runs` → bus → orch → LLM stages → execution fan-out → Manager/Delivery → signed download).

P0 · blockers before any external use

Monolith-era P0s are addressed by M1–M7 / S0–S6. Keep these as honesty checks — not as “still broken.”

P0 Postgres hard-disabled — shipped (M1)

P0 Minimal execution ≠ E2E proof — still true

Most scale walls are closed; watch these when adding tenants or cloud providers.
