Architecture Docs

ZER0

Runtime today, the production blueprint, the agent prompt to build it, and the ship checklist — one page, five tabs. Grounded in server.js + lib/, aimed at the multi-cloud target in docs/ARCHITECTURE.md.

What ZER0 is for

One tool that compresses the QA architect + BA + manual + automation workflow behind a single URL.

Give ZER0 an OTT URL and any of a test-case file, Figma link, or plain notes. It produces consolidated requirements, an app-specific manual test-case list, Playwright + Java/Selenium scripts, a Playwright execution report with screenshots, and Manager / Delivery reports as PDF or JSON.

The point is not "another test recorder." It's a single run that turns a link into a full QA artifact set — usable by a solo QA on day one and portable into your real Java/Maven suite when you want production coverage.

Who it's for

Built for teams doing OTT / streaming / e-commerce QA under time pressure.

QA architects & leads

Need consistent BRD → TC → script → report traceability across many channels. Get it in one run.

Solo QA on a new product

No test suite yet. Feed the site URL, pick a profile, get a manual list and a Java suite you can adapt.

Delivery managers

Need a stakeholder-ready Manager / Delivery report per run without chasing four people for pieces.

Automation engineers

Use the generated Playwright spec and Java/Selenium class as scaffolding; own execution in your own CI.

How people use it

Six steps, from browser open to shippable report.

02

03

06

Take Java to prod

Drop the generated Java class into your Maven/Gradle project, tune the locators for your app, run in your CI.

How it works under the hood

A single Express process orchestrates the pipeline; Playwright drives a real Chromium locally.

  1. Intake: UI POSTs a multipart form to /api/runs. server.js creates the run, stores it in an in-memory Map and on disk at artifacts/<runId>/run.json.
  2. Stages: processRun walks stageKeys. Each agent is a deterministic template today — no LLM required — that consolidates inputs into typed artifacts.
  3. Locators: lib/locatorRegistry.js merges channel-profile selectors + this-run learned selectors + (when enabled) Postgres locators per host.
  4. Execution: playwright.chromium.launch() runs each test case; screenshots and traces land under artifacts/<runId>/.
  5. Reports: pdfkit renders the Manager PDF; a Delivery report is emitted as JSON. The UI polls GET /api/runs/:id until status is completed.
  6. Reuse: the Java/Selenium class is generated by lib/javaSeleniumBuilder.js from the same locator merge, so you can lift it into any Java project.

Recording bookmarklet + /record page lets you capture real DOM element logs from any site; those feed the locator registry too.

How to run

From the repository root.

npm install
npx playwright install chromium

# builds the React client into public/
npm run build

# starts Express (default PORT=3000)
npm start

Paste-safe: run each line separately. zsh has INTERACTIVE_COMMENTS off by default, so inline # comments get forwarded to vite build and the build fails with Could not resolve entry module "#/index.html". Enable once with setopt interactive_comments.

  • Input: OTT URL required, plus at least one of Figma / TC file / BA notes (or Web Analyzer fills gaps).
  • Default execution: minimal — load URL + screenshot so the pipeline completes.
  • Full mode: EXECUTION_MODE=full for keyword/selector navigation (brittle).

Postgres is hard-disabled in server.js (databaseConfigured() returns false). Runs persist to artifacts/<id>/run.json + in-memory Maps until that stub is restored.

Why the shape has to change

Today's runtime hits five walls before it can go multi-tenant on any cloud.

Serverless ≠ Playwright

Vercel functions can't host long-running Chromium. Execution must move to a durable worker host.

State in Maps

runs, runSecrets, recordingSessions, selectorMemory — all in-process. Zero horizontal scale.

Local disk artifacts

artifacts/ is a filesystem path. Serverless has no persistent disk; workers can't share it.

API does the work

processRun runs stages inside the request. Retries, back-pressure, and fan-out are impossible.

Postgres optional

Once orchestrators scale out, memory can't hold state. DB + Redis become required, not optional.

Vendor-shaped code

To move between AWS / GCP / Azure the domain code must stop knowing which SDK it's talking to.

Three tiers with one contract

Split ZER0 into stateless intake, orchestration workers, and ephemeral execution — everything else hides behind adapters.

  Tier              Runtime                       Owns
  ────────────────────────────────────────────────────────────────
  edge + api        stateless containers /         auth, run intake,
                    serverless functions           status stream, signed URLs

  orchestration     long-lived workers             BA · Manual · Automation ·
                                                   Manager · Delivery agents,
                                                   LLM calls, DAG state

  execution         ephemeral job containers       Playwright chromium runs,
                                                   screenshots, element logs

Contract: every tier only talks to four provider-agnostic primitives — queue, object store, relational DB, and KV / secrets. Cloud SDKs live in lib/cloud/* adapters, never in agents.

Cloud adapter contracts

Tight interfaces so the domain code never imports a vendor SDK.

// lib/cloud/index.d.ts

export interface ObjectStore {
  presignPut(key: string, ttlSec?: number): Promise<string>;
  presignGet(key: string, ttlSec?: number): Promise<string>;
  put(key: string, body: Buffer | Readable, meta?: object): Promise<void>;
  get(key: string): Promise<Readable>;
  remove(key: string): Promise<void>;
}

export interface Queue<T> {
  publish(topic: string, msg: T, opts?: { dedupId?: string }): Promise<void>;
  subscribe(topic: string, handler: (msg: T) => Promise<void>): Unsubscribe;
}

export interface Secrets {
  get(name: string): Promise<string>;
  put(name: string, value: string): Promise<void>;
}

export interface Cache {
  get<T>(key: string): Promise<T | null>;
  set<T>(key: string, val: T, ttlSec?: number): Promise<void>;
  publish(channel: string, msg: unknown): Promise<void>;
  subscribe(channel: string, cb: (msg: unknown) => void): Unsubscribe;
}

## North-star shape (do not redesign)
Three tiers, one contract:
- **API** — auth, run intake, status/SSE, signed URLs. Never runs Chromium.
- **Orchestrator** — BA · Manual · Automation · Manager · Delivery, LLM calls, DAG state. Consumes `runs.requested`.
- **Execution farm** — ephemeral Playwright jobs on `execution.requested`; screenshots/traces to object store.

Every tier talks only through provider-agnostic primitives in `lib/cloud/*`:
`queue` · `object store` · `relational DB` · `KV/cache` · `secrets`.
Wire once from `process.env.ZERO_CLOUD` = `aws` | `gcp` | `azure` | `vercel`. Domain/agent code must not import vendor SDKs.

Honor the numbered start-to-report sequence on the blueprint page (presigned uploads → Postgres `qa_runs` → bus → orch → LLM stages → execution fan-out → Manager/Delivery → signed download).

## Milestone order (ship in order; each unblocks the next)
- **M1 Durable store** — Restore real `databaseConfigured()` / `initDatabase()`. Wire Postgres for `qa_runs`, `qa_assets` (add DDL if missing), `element_locators`, and related tables in `lib/db.js`. Kill reliance on in-memory `runs` / `runSecrets` / `recordingSessions` / `selectorMemory` Maps for durability.
- **M2 Object store + signed URLs** — Move `artifacts/` off local disk. Browser uploads via presigned PUT; API never streams large bodies. Screenshots/reports via presigned GET.
- **M3 Queue + orchestrator** — Extract `processRun` into a worker consuming `runs.requested`. API returns immediately; progress via Redis pub/sub → SSE.
- **M4 Execution farm** — Playwright in container jobs behind `execution.requested`. Fan-out per TC batch; retries via queue; concurrency caps.
- **M5 Auth + ACL** — Real OIDC (or verified API keys). Per-tenant scoping on runs/artifacts. Stop spoofable `X-User-Email` and “any non-empty x-api-key”. No public `/artifacts`; recording CORS not `*`.
- **M6 LLM wiring** — Provider keys UI actually drives BA/Manager (and Manual/Automation as designed). Rate limits, cost caps, prompt versioning. Until wired, do not claim LLM agents are live.
- **M7 Multi-cloud adapters** — `lib/cloud/*` for AWS + one other; IaC per provider; CI smoke.

## Ship Checklist constraints (fix while building)
P0: Postgres hard-disable, no real auth, public artifacts + open recording CORS, in-process unbounded Playwright, minimal execution ≠ E2E proof.
P1: memory-bound state, wrong host for Chromium on serverless, default `KEY_ENC_SECRET`, missing tests/CSP/CORS hygiene.
P2: disconnected LLM UI, unfinished IDE/projects vision, monolith split as needed for workers — keep focused; no drive-by refactors of all of `server.js`.

## Product rules to preserve
- Pipeline order: optional `webAnalyzer` → `ba` → `manualQa` → `automationQa` → `execution` → optional a11y/perf/security → `manager` → `delivery`.
- Locator merge: profile → memory → DB (`lib/locatorRegistry.js`).
- Default `EXECUTION_MODE=minimal` stays honest (URL load ≠ release proof); `full` is opt-in/brittle.
- Never log or persist login passwords; secrets via secrets manager / `runSecrets` equivalent only.
- UI source is `client/src/**`; rebuild with `npm run build`. Prefer extracting workers/routers into `lib/` only when matching existing boundaries.

## How to work
1. Run `npm run workflow:status` (or `/zero-target-arch`) — start at the earliest unfinished milestone.
2. Small, reviewable PRs per milestone; update `docs/ARCHITECTURE.md` and this HTML only when behavior changes.
3. Prefer adapters + interfaces first, then one concrete provider (`local` or AWS) so local/dev still runs.
4. Add CI smoke: health + one hermetic path; do not treat Manager “Go” as E2E without full mode or external runners.
5. When done with a milestone, run `npm run workflow:verify`, update `agent-workflow/progress.json`, and state what flipped from “target” to “shipped”.

## Acceptance for “Target architecture is real”
- API is stateless; Chromium only in execution workers.
- Run state and artifacts survive multi-instance restarts (Postgres + object store + Redis).
- Uploads/downloads are signed; artifacts are not world-readable.
- Auth scopes tenants; no spoofable identity headers.
- Agents/orchestrator communicate via queues; cloud SDKs only under `lib/cloud/*`.
- Milestones M1–M4 complete at minimum; M5–M7 planned or partially landed with clear gaps called out.

Implement the next unfinished milestone now. Ask before destructive migrations or changing public API contracts.

P0 · blockers before any external use

These are correctness or safety issues, not polish.

P0 Postgres hard-disabled

databaseConfigured() returns false; locator reuse, qa_assets, projects, and key persistence never activate. Restore init or drop SQL claims.

P0 No real auth

Identity is a spoofable X-User-Email; apiKeyAuth accepts any non-empty key. Runs and artifacts are unscoped.

P0 Public artifacts + open recording CORS

/artifacts is static-served; recording POSTs set Access-Control-Allow-Origin: *.

P0 In-process Playwright, no queue

processRun launches Chromium in the API process with no concurrency cap — multi-run DoS / OOM risk.

P0 Minimal execution ≠ E2E proof

Default checks pass on URL load. Manager "Go" must not be treated as release proof without full mode or external runners.

P1 · gaps before scale

These bite the moment there's more than one instance or user.

P1 Memory-bound state

Runs, recordings, secrets, selector memory are Maps — broken across instances and restarts (except run.json).

P1 Wrong host for Playwright

Vercel /tmp + serverless timeouts vs long Chromium work; need a durable worker host.

P1 Default encryption secret

KEY_ENC_SECRET falls back to a fixed dev string — refuse to start in production without it.

P1 Ops / config

No tests despite Jest; CSP allows unsafe-eval; CORS wildcards for Railway/Vercel; example env embeds a live hostname.

P2 · later

Real improvements, but not blockers.

P2 LLM UI is disconnected

Provider keys + agent settings APIs exist; BA/Manager never call Claude/OpenAI/Gemini.

P2 IDE vision unfinished

No /api/projects; stored scripts / recordings tables unused while DB is off.

P2 Monolith + middleware order

Split routers/worker from server.js; fix duplicate error handlers vs SPA catch-all.

Recommended sequence

One right order to attack the list without wasted work.

  1. Unlock durable store — turn Postgres back on and wire the real tables.
  2. Auth + artifact ACL — replace header-based identity, presign artifact reads.
  3. Queued Playwright workers — move Chromium out of the API process.
  4. Honest Go / No-Go semantics — minimal execution stops implying release proof.
  5. Wire or defer LLM — either connect the key UI, or hide it until it works.
  6. CI smoke + container image — one repeatable image, one green test path.
